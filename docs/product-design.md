> 版本：v2.0（自然活力版，新增营养素对比模块）  
> 日期：2026-10-11  
> 状态：待评审

## 1. 产品概述

### 1.1 产品定位
一款**个人自用**的手机 App（Android / iOS），用于统一管理「药品」和「保健品」的**服用计划、到点提醒、服用记录与库存**。

一句话定位：**"到点提醒我，按一下记录我吃了，随时回看我到底吃得规不规律。"**

### 1.2 核心决策（已确认）
| 决策项 | 结论 |
|---|---|
| 目标用户 | 自己用（个人工具，暂不考虑家庭协作） |
| 覆盖范围 | 药品 + 保健品，**统一数据模型**，用类型字段区分 |
| 平台 | 手机 App，Flutter 跨平台（Android 优先，iOS 兼容） |
| 数据 | **本地优先**（SQLite），架构预留可选云同步 |
| 提醒 | 到点单次提醒 + 通知快捷操作（已服用 / 稍后） |
| 技术栈 | Flutter + Dart |

### 1.3 设计原则
1. **首页即行动**：打开 App 第一眼只回答一个问题——"现在有没有该吃的？"（借鉴 DoseLoop 的"当前优先"理念）
2. **3 秒闭环**：从通知或首页完成一次记录不超过 3 秒、不超过 1 次点击
3. **记录必留痕**：每次计划服用都有明确终态：已服用 / 跳过 / 漏服，不允许"提醒响过就消失"
4. **药与保健品一视同仁**：同一套模型，差异只体现在 UI 文案和少量扩展字段
5. **隐私底线**：数据不出设备；App 不提供任何医疗建议

### 1.4 竞品对标结论（做什么 / 不做什么）
| 做（MVP 核心） | 不做（本期砍掉的） |
|---|---|
| 到点提醒 + 通知快捷确认 | 闭环持续追提醒（5/15/30 分钟轰炸式）→ 二期 |
| 四状态记录（已服/跳过/漏服/待确认） | 家庭协作 / 多人共享 → 远期 |
| 灵活频率（每天/每周几/隔N天/吃N停M/按需） | 药物相互作用警告（需专业数据库）→ 远期 |
| 库存管理 + 低库存提醒 | 扫码/拍照录入成分 → 二期以后 |
| **营养素摄入 vs DRIs 对比（差异化核心）** | 账号体系（云同步预留接口，MVP 不做） |
| 日历历史 + 依从率统计 | PDF 报告、医生分享 → 二期 |
| 数据导出（CSV） | 食物/膳食摄入记录 → 远期 |

### 1.5 视觉设计语言：自然活力（Natural Vitality）
> 评审结论：初版"医疗蓝绿 + 圆角卡片"过于模板化，确立以下专属设计语言。

| 要素 | 规范 |
|---|---|
| 色彩 | 奶油底 `#F6F1E7`、苔藓绿主色 `#5F8D4E`、陶土橙强调 `#E07A5F`、蜂蜜黄 `#F2CC8F`、暖红警示 `#D4654F`、深棕墨文字 `#3E3A33` |
| 形状 | 24px 大圆角卡片；**胶囊形**按钮、进度条、Tab 栏（呼应"药丸"产品主题） |
| 游戏化 | **「每日灌溉」养成隐喻**：连续打卡 = 浇灌植物，阶段为 🌱种子→🌿小苗→🪴茁壮→🌻盛开；当日全部确认触发"浇水"反馈 |
| 动效 | 打卡按钮弹跳（pop）、已服徽章弹入（donePop）、营养进度条 0→目标值缓动（cubic-bezier(.22,1,.36,1)）、植物摇摆（sway） |
| 质感 | 暖色阴影 `rgba(93,80,60,.09)`、虚线分隔、奶油渐变装饰，拒绝冷硬医疗感 |
| 参考气质 | Finch / Streaks 的轻松养成感，而非医院/药房感 |

## 2. 使用场景与用户故事

**S1 每日服用**：早上 8:00 手机弹出通知"维生素D3 1粒"，用户在通知上直接点【已服用】，全程不开 App。

**S2 漏服回看**：周末翻了下日历视图，发现上周三晚上的鱼油标记为红色"漏服"，心里有数。

**S3 新开一种药**：医生开了阿利沙坦酯，每天早 1 片，吃 30 天。用户 2 分钟内建好计划：名称、选颜色、每天 08:00、起止日期、库存 30 片。

**S4 周期用药**：某保健品要求"吃 5 天停 2 天"，建计划时选周期循环模式即可，无需每天手动开关。

**S5 补药**：库存剩 5 天时，首页出现低库存提示，用户下单补货后一键补登库存。

**S6 临时吃一次药**：头疼吃了一片布洛芬，这种"按需"药物不进提醒，但可以在药箱里快速"记一笔"。

**S7 当天补记**：晚上想起早上的药实际吃了但忘记录，在今日页补点"已服用"，实际时间自动记为补录时间（可改）。

**S8 营养对比（新增）**：同时吃着 D3（每粒 25μg 维生素D）、复合维生素（每片含 20μg）和钙片，在「营养」Tab 看到维生素D 合计 45μg、已超推荐量 10μg 但逼近上限 50μg，提示"接近每日上限"——于是知道复合维生素和 D3 不必同一天都吃，避免了重复摄入。

## 3. 核心概念与数据模型

### 3.1 领域模型

```
┌──────────────┐ 1     * ┌──────────────┐
│  Medication  │─────────│   Schedule   │   （一个药可有多条计划：
│  药品/保健品  │         │   服用计划    │    如"早1片、晚2片"）
└──────┬───────┘         └──────┬───────┘
       │ 1                      │ *
       │        *        *      │
       └────────┤ IntakeEvent  ├┘
                │   服用事件     │   （每次"该吃了"生成一条，
                └──────────────┘     最终必有终态）
```

### 3.2 表结构详细设计

#### 3.2.1 `medications`（药品/保健品主表）
| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT (uuid) | 主键，uuid 便于将来云同步 |
| name | TEXT | 名称，如"维生素D3" |
| type | TEXT | `medicine` 药品 / `supplement` 保健品 |
| form | TEXT | 剂型：`tablet`片 `capsule`粒 `liquid`液体 `powder`粉 `gummy`软糖 `injection`注射 `other` |
| color | INT | 颜色标识（色板选色，列表快速辨认） |
| icon | TEXT | 图标标识（可选） |
| instruction | TEXT | 服用说明，如"随餐""空腹""睡前"（预设标签+自定义） |
| note | TEXT | 自由备注 |
| stock_enabled | BOOL | 是否启用库存追踪 |
| stock_remaining | REAL | 当前库存（按剂量单位） |
| low_stock_days | INT | 低库存阈值（按"还能吃几天"计，默认 7） |
| is_active | BOOL | 启用 / 暂停（暂停不生成事件、不提醒） |
| is_deleted | BOOL | 软删除（云同步需要） |
| created_at / updated_at | INT | 时间戳（云同步需要） |

#### 3.2.2 `schedules`（服用计划表）
| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT (uuid) | 主键 |
| medication_id | TEXT | 外键 |
| freq_type | TEXT | `daily` 每天 / `weekly` 每周指定日 / `every_n_days` 每隔N天 / `cycle` 吃N停M / `as_needed` 按需 |
| weekdays | TEXT(JSON) | freq=weekly 时：`[1,3,5]`（周一三五） |
| interval_days | INT | freq=every_n_days 时：间隔天数 |
| cycle_on / cycle_off | INT | freq=cycle 时：吃N天 / 停M天 |
| times | TEXT(JSON) | 时间点数组 `[{"time":"08:00","dose":1.0},{"time":"20:00","dose":2.0}]`，**支持不同时间不同剂量** |
| dose_unit | TEXT | 剂量单位：`片/粒/mg/g/ml/IU/袋/滴`（每药可不同，冗余在计划上便于统计） |
| start_date | TEXT | 开始日期 |
| end_date | TEXT(NULL) | 结束日期，NULL=长期 |
| created_at / updated_at | INT | |

> `as_needed`（按需）模式：不生成计划事件、不提醒，仅在药箱提供"记一笔"按钮，事件直接生成 `taken` 状态。

#### 3.2.3 `intake_events`（服用事件表）
| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT (uuid) | 主键 |
| medication_id | TEXT | 外键（冗余，便于按药查询） |
| schedule_id | TEXT | 外键 |
| plan_date | TEXT | 计划日期 `2026-10-11` |
| plan_time | TEXT | 计划时间 `08:00` |
| plan_dose | REAL | 计划剂量 |
| status | TEXT | `pending` 待确认 / `taken` 已服用 / `skipped` 跳过 / `missed` 漏服 |
| actual_time | INT(NULL) | 实际服用时间戳 |
| actual_dose | REAL(NULL) | 实际剂量（默认同计划，可调） |
| note | TEXT | 单次备注，如"服后略恶心" |
| created_at / updated_at | INT | |

**事件生命周期（关键机制）：**
- **生成**：App 启动时 + 每天 00:05 本地闹钟，为「未来 1 天」的所有有效计划生成 `pending` 事件（幂等：同 plan_date+plan_time+schedule 不重复生成）。补生成机制保证 App 几天不开也能补齐历史事件。
- **漏服判定**：超过「确认窗口」仍为 `pending` 的事件，由 App 启动时统一批改为 `missed`。确认窗口默认 = 计划时间 + 4 小时（可在设置调整）。
- **库存扣减**：`pending → taken` 时按 actual_dose 扣减 `stock_remaining`；`taken → 撤销` 时回补。

#### 3.2.4 `nutrients`（营养素字典表，内置只读）
对照**中国营养学会《中国居民膳食营养素参考摄入量（2023 版）》**（DRIs）预置，随 App 版本更新。
| 字段 | 类型 | 说明 |
|---|---|---|
| code | TEXT | 主键，如 `vd` `vc` `ca` `fe` `omg` |
| name | TEXT | 中文名，如"维生素D" |
| unit | TEXT | 计量单位：`μg/mg/μgRAE` |
| category | TEXT | `vitamin` 维生素 / `mineral` 矿物质 / `fatty_acid` 脂肪酸 / `other` |
| rni_male / rni_female | REAL | 成人推荐摄入量（分性别，无性别差异时两值相同） |
| ai_value | REAL(NULL) | 适宜摄入量（无 RNI 时使用，如 Omega-3 250mg） |
| ul_value | REAL(NULL) | 可耐受最高摄入量，NULL=未设定（如镁、B12） |

预置范围（V1.0）：维生素 A/B12/C/D、钙、铁、锌、镁、Omega-3（EPA+DHA），共 9 种；数据结构支持后续扩充（硒、叶酸、B族细分等）。

#### 3.2.5 `product_ingredients`（产品成分表，仅保健品使用）
| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT (uuid) | 主键 |
| medication_id | TEXT | 外键 |
| nutrient_code | TEXT | 外键 → nutrients.code |
| amount_per_unit | REAL | 每 1 单位（片/粒）含量，单位同 nutrients.unit |

#### 3.2.6 `profile`（人群档案，设置项）
存 shared_preferences：`adult_male`（默认）/ `adult_female`。影响 DRIs 取值（如铁 RNI 男 12mg / 女 20mg，维生素A 男 800 / 女 700 μgRAE）。远期可扩展孕期/老年等人群。

**每日摄入计算规则：**
```
某营养素当日摄入量 = Σ (当日 status=taken 的事件.actual_dose × 该药 product_ingredients.amount_per_unit)
```
- 药品（medicine）不参与营养素统计（通常无成分录入）
- `as_needed` 事件为 taken 时同样计入
- 状态展示三档：`amount < RNI` 未达标（蜂蜜黄）/ `RNI ≤ amount` 已达标（苔藓绿）/ `UL 且 amount > UL` 超上限（陶红警示 + 文案"请勿继续服用并咨询医生"）；`amount ≥ 0.8×UL` 时提示"接近每日上限"

### 3.3 关键设计决策说明
1. **为什么事件要物化落库**（而非查询时动态计算）：历史必须不可变、支持补记与备注、统计查询简单、将来云同步以事件为单位。
2. **为什么计划与药分离**：支持同一药品多个服用方案（如早晚不同剂量），将来换药量时"结束旧计划、新建新计划"，历史不丢失。
3. **云同步预留**：所有表 uuid 主键 + `updated_at` + 软删除，将来接入 Supabase/PowerSync 时无需改模型。

## 4. 信息架构与页面设计

### 4.1 导航结构（底部 5 Tab，悬浮胶囊 Tab 栏）
```
┌────────┬────────┬────────┬────────┬────────┐
│  今日   │  营养   │  记录   │  药箱   │  设置   │
│  ☀️    │  🥗    │  📅    │  🧺    │  ⚙️    │
└────────┴────────┴────────┴────────┴────────┘
```

### 4.2 Tab 1：今日（行动中心）
**布局（自上而下）：**
1. **植物成长 Hero**：左侧当前植物阶段（🌱→🌿→🪴→🌻，带摇摆动画）+ 阶段名与"连续灌溉 N 天"；右侧今日待办概览（"还有 X 项待服用"）+ 胶囊形进度条（蜂蜜黄→苔藓绿渐变）；**全部确认后触发"浇水"反馈**，植物进入当日盛开态
2. **待办区（默认置顶）**：所有 `pending` 事件按时间排序的卡片列表
   - 卡片内容：左侧颜色条 + 剂型emoji + 药名 + 类型标签（药/保）+ 剂量（"1 片"）+ 计划时间 + 服用说明标签
   - 操作按钮：**【已服用】（胶囊主按钮，点击弹跳）** 【跳过】
   - 已过时间未确认的卡片显示"已超时"（暖红左边条 + 暖红底），醒目但不刺眼
3. **已完成区（折叠）**：今日 `taken/skipped/missed` 事件，置灰展示，支持"撤销"回退到 pending（库存回补）
4. 低库存横幅（如有）：蜂蜜色虚线卡片，"维生素D3 还能吃 5 天 · 去补货"

**空态**：今日无计划 → 植物插画 + 连续打卡天数 + 正向文案。

### 4.3 Tab 2：营养（营养素摄入 vs DRIs，差异化核心模块）
**布局：**
1. **顶部概览卡**（苔藓绿渐变）：今日已摄入营养素 X 种 · 达标 Y 种；副标题注明对照标准
2. **营养素列表**（按 维生素 / 矿物质 / 脂肪酸 分组），仅展示当日有摄入的条目：
   - 名称 + 单位 + 参考类型（RNI 推荐量 / AI 适宜量）
   - **双刻度进度条**：蜂蜜黄填充（未达标）→ 苔藓绿填充（已达标）→ 陶红填充（超 UL）；条上标 **RNI 刻度线**与 **UL 红色刻度线**（如有）
   - 状态文案：`还差 40mg 达标` / `✓ 已达推荐摄入量` / `⚠️ 接近每日上限（45/50μg）` / `⛔ 已超每日上限，请勿继续服用并咨询医生`
   - **来源拆分** chips：`🌞维生素D3 +25μg` `🧬复合维生素 +20μg`（点击可跳药品详情）
3. **底部说明卡**：参考标准来源（DRIs 2023）、RNI/AI/UL 释义、"仅统计补充剂、不含膳食摄入、不构成医疗建议"声明
4. 空态：当日无含成分摄入 → 引导去药箱为保健品录入成分

**联动**：今日页确认/撤销服用 → 本页进度条实时增减（0.8s 缓动动画）。

### 4.4 Tab 3：记录（历史 + 统计）
**上半：日历视图**
- 月历，每天一个状态点：绿=全部完成 / 黄=有跳过 / 红=有漏服 / 灰=无计划
- 点日期进入「当日明细」：按时间列出所有事件及其状态，支持补记（把 missed/pending 改为 taken 并填实际时间）

**下半：统计卡片**
- 近 7 天 / 30 天依从率（圆环）：`taken / (taken+skipped+missed)`
- 按药品分列的依从率条形列表
- 连续灌溉天数（植物养成 streak 总览）

### 4.5 Tab 4：药箱（药品列表）
- 分两组展示：**药品** / **保健品**
- 每行：色块 + 名称 + 摘要（"每天 · 08:00 · 1片"）+ 🌱连续 N 天（保健品）+ 成分数（"含3种成分"）+ 库存角标
- 右上角 `+` 新增；左滑：暂停 / 删除
- 点击进入**详情页**：基础信息、服用计划、**营养成分卡（每单位含量，仅保健品）**、今日状态、近 30 天依从率、库存调整、编辑/暂停/删除

### 4.6 Tab 5：设置
- **营养参考**：人群档案（成年男性/成年女性，影响 DRIs 取值）
- 提醒设置：通知开关、确认窗口时长（默认 4h）、提醒铃声/震动
- 通知权限引导（含国产 ROM 电池优化白名单引导说明）
- 数据管理：导出 CSV、导入、清空数据
- 免责声明（含营养素参考值来源说明）、关于

### 4.7 关键流程：新增（目标 ≤ 2 分钟）
```
选类型(药/保健品) → 名称+剂型+颜色+服用说明
→ [仅保健品] 成分录入（营养素+每单位含量，可跳过）
→ 频率模式(每天/每周几/隔N天/吃N停M/按需)
→ 时间点+剂量(可加多个) → 起止日期(默认明天起,长期)
→ 库存(可选: 当前数量+低量阈值) → 完成
```
- 分步表单，步骤条随类型动态增减（药品无成分步骤，5 步；保健品 6 步）
- 成分录入引导文案："查看包装上的营养成分表，如「每粒含维生素D 25μg（1000IU）」即填 25"
- 每步有合理默认值，除名称外全部可跳过（先建后补）

## 5. 提醒系统设计

### 5.1 提醒行为
- 每个计划时间点生成一条**本地通知**（不依赖网络、不依赖服务器）
- 通知内容：`该吃 [药名] 了 · 1 片 · 随餐`
- 通知快捷操作（Action）：**【已服用】** / **【稍后 10 分钟】**
  - 点【已服用】：事件直接置 `taken`，扣库存，无需打开 App
  - 点【稍后】：10 分钟后再发一次（最多顺延 3 次，之后保持 pending 待 App 内处理）
- 通知被划掉/忽略：事件保持 `pending`，超过确认窗口后判 `missed`（在记录页可见，可补记）

### 5.2 通知调度策略
- 事件生成时，通过 `flutter_local_notifications` 的 **zonedSchedule** 精确调度当日全部通知
- App 启动 / 计划变更时全量重排未来 7 天通知（Android 对排队通知数量有限制，滚动重排）
- 设备重启后：监听 `BOOT_COMPLETED`（Android）重排通知

### 5.3 平台适配要点
| 平台 | 事项 |
|---|---|
| Android 13+ | 运行时申请 `POST_NOTIFICATIONS` 权限 |
| Android 12+ | 精确闹钟需 `SCHEDULE_EXACT_ALARM` 权限，首启引导用户授予 |
| 国产 ROM（小米/华为/OPPO/vivo） | 提供"保活引导"页：引导开启自启动、关闭电池优化（用药提醒类 App 的已知痛点，Medisafe 同样如此） |
| iOS | 申请通知授权；iOS 本地通知上限 64 条，滚动调度未来 7 天 |

## 6. 统计与激励

- **依从率**：近 7/30 天，`taken / (taken+skipped+missed)`，`as_needed` 事件不参与依从率
- **植物养成（核心激励）**：当日全部事件确认 → 触发"浇水"；连续无漏服天数驱动植物阶段成长：🌱种子(0-3天)→🌿发芽(4-13)→🪴茁壮(14-29)→🌻盛开(30+)；漏服一天退回上一阶段（温和惩罚，不清零）
- **营养达标率**：当日有摄入的营养素中，达 RNI/AI 的比例（营养页概览卡展示）
- **日历热力**：月历色点，一眼识别漏服日
- **激励（轻量）**：连续 7/30/100 天徽章，仅在记录页展示，不打扰

## 7. 技术架构

### 7.1 技术选型
| 层 | 选型 | 理由 |
|---|---|---|
| 框架 | Flutter 3.x (stable) | 一套代码双端，本地通知生态成熟 |
| 状态管理 | **Riverpod** (flutter_riverpod) | 编译期安全、可测试、社区主流 |
| 本地数据库 | **Drift** (SQLite) | 类型安全 SQL、支持迁移、Stream 查询与 Riverpod 天然配合 |
| 本地通知 | flutter_local_notifications + timezone | 双端统一封装，支持 Action 按钮与精确调度 |
| 路由 | go_router | 官方推荐，声明式 |
| 图表 | 营养进度条用 CustomPaint 自绘（双刻度），依从率条形用轻量绘制即可 | 进度条为自定义控件，无需引入图表库 |
| 设置存储 | shared_preferences | 简单键值 |
| 序列化 | json_serializable / Drift 内置 | |
| 导出 | csv + share_plus / path_provider | 导出 CSV 分享 |

### 7.2 代码结构（feature-first）
```
lib/
├─ main.dart
├─ app/                  # 路由、主题、启动逻辑
├─ core/
│  ├─ database/          # Drift 表定义、DAO、迁移
│  ├─ notifications/     # 通知封装：调度/重排/Action回调
│  ├─ scheduler/         # 事件生成器、漏服判定器
│  └─ utils/
├─ features/
│  ├─ today/             # 今日页（视图+控制器）
│  ├─ nutrition/         # 营养页（摄入汇总、DRIs 对比、双刻度进度条）
│  ├─ cabinet/           # 药箱（列表/详情/新增编辑向导）
│  ├─ history/           # 日历、当日明细、补记
│  ├─ stats/             # 依从率、植物养成
│  └─ settings/          # 设置、人群档案、导出、权限引导
└─ l10n/                 # 中文优先，预留多语言
```

### 7.3 核心服务
1. **EventGenerator（事件生成器）**：`generateForDateRange(from, to)`，按 schedule 的 freq_type 计算应生成的事件，幂等插入。触发时机：App 启动、计划增改、每日 00:05 闹钟。
2. **MissedMarker（漏服判定器）**：App 启动 + 前台定时器，把 `plan_time + 确认窗口 < now` 且仍 `pending` 的事件批量置 `missed`。
3. **NotificationScheduler（通知调度器）**：监听事件/计划变化的 Stream，全量取消并重排未来 7 天通知；处理通知 Action 回调（含 App 被杀时由 `onDidReceiveBackgroundNotificationResponse` 处理）。
4. **StockService**：`taken` 时扣减、撤销回补、低库存判定（remaining / 日均消耗 ≤ low_stock_days 时产生提示）。
5. **NutritionService**：`summarizeDay(date)` 汇总当日 taken 事件的营养素摄入（金额 × 成分含量），对照 `nutrients` 字典按人群档案取 RNI/AI/UL，输出每条的三档状态（未达标/已达/超上限/接近上限）与来源拆分；供营养页与详情页成分卡消费。事件状态变化时失效重算（Stream 缓存）。
6. **DrisRepository**：DRIs 2023 内置字典数据（随 App 版本更新，完全不联网），提供按 code 查询与旁路注入 V1.0 mock 数据相同的测试集。

### 7.4 云同步预留（二期，不在 MVP 实现）
- 候选方案：Supabase（Postgres + Auth，成本低）或 PowerSync（离线优先同步引擎）
- 模型已预留 uuid / updated_at / 软删除，届时加 `sync_state` 字段即可

## 8. 隐私、合规与安全

1. 数据全部存于设备本地，无任何服务器上报、无统计埋点（MVP）
2. 首次启动与设置页固定展示免责声明：**"本应用仅提供服用提醒与记录功能，不构成医疗建议、诊断或治疗依据。用药请遵医嘱。"**
3. 营养素参考值明确标注来源（中国营养学会《中国居民膳食营养素参考摄入量 2023》），并注明"仅统计补充剂、不含膳食摄入，结果仅供参考"
4. 超过 UL 时给出**保守文案**（"请勿继续服用并咨询医生"），不进行任何"该多吃/少吃"的主动干预建议
5. 导出 CSV 由用户主动触发，经系统分享面板转出，App 不持有副本
6. 将来若做相互作用检查，仅基于内置静态数据在本地完成，标注"仅供参考"
