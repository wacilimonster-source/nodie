# 功能设计：保健品预置模板 + AI 解析录入

> 版本：v1.0（草案）· 待确认 · 目标版本 v1.4.0
> 关联：`product-design.md`（主设计）、`tech-architecture.md`（架构）

---

## 1. 背景与目标

现状：新增保健品需逐个照标签手填成分，耗时长、易漏。
目标：**两条快速录入通道**，把「一盒多成分」的录入从几分钟降到几秒：

| 通道 | 适用 | 依赖 |
|---|---|---|
| **A. 预置模板** | 常见品类（复合维生素、鱼油、钙+D3+K2…） | 内置配方库 + 用户自建 |
| **B. AI 解析** | 任意具体产品（如你手上的 Swisse） | 用户用豆包等大模型拍照 → 回贴文本 |

> 关键洞察：**智能体已经能做"拍照+识字+结构化"**，App 不必内嵌 OCR。
> App 提供**规范提示词**，大模型按格式输出，App 只做**严谨解析 + 人工确认**。
> 优点：零成本、零 API Key、不依赖 Google 服务（国产 ROM 友好）、隐私（App 本身不上传任何数据）。

---

## 2. 方案总览（新增向导入口）

```
选类型(保健品)
 ├─ ★ 从模板添加     ← 通道 A
 ├─ 🤖 AI 解析录入    ← 通道 B（复制提示词 / 粘贴结果）
 └─ ＋ 从空白创建
→ 自动填充 名称 + 剂型 + 成分表(每单位含量) + 建议用法
→ 用户可编辑 → 可「保存为我的模板」
```

## 3. 通道 A：预置模板

### 3.1 三层结构
| 层 | 内容 | 来源 | 可编辑 |
|---|---|---|---|
| **L1 内置通用配方** | ~35 个通用配方（不绑品牌） | 随 App 内置，随版本更新 | 是（预填≠锁定） |
| **L2 我的模板** | 用户自建/从识别结果保存 | 本地 | 是 |
| **L3 远端配方库** | `presets.json` 经 jsDelivr 增量下发 | 云端（可选） | 是 |

### 3.2 内置配方清单（v1，~35）
- **基础营养**：复合维生素(男/女)、复合维生素+矿物质、B族复合、维C、维D3、维D3+K2、维E、铁、锌
- **骨骼关节**：钙+D3、钙+D3+K2、氨糖软骨素、胶原蛋白+VC、MSM
- **心脑血管**：鱼油(常规/高浓)、磷虾油、辅酶Q10、纳豆激酶、叶酸+B族
- **免疫抗氧化**：维C、蜂胶、硒、锌、紫锥菊
- **护眼**：叶黄素+玉米黄质、越橘花青素
- **肠道**：益生菌(多菌株)、菊粉/膳食纤维
- **美容**：胶原蛋白肽、葡萄籽原花青素、生物素、透明质酸
- **睡眠情绪**：褪黑素、GABA+茶氨酸、甘氨酸镁
- **女性**：孕期复合维生素、月见草油、蔓越莓、大豆异黄酮
- **男性**：男士复合维生素、锌+硒、番茄红素

> 每个配方挂「仅供参考，请以实物标签为准」+ 更新日期；成分值均为**可编辑的近似值**。

### 3.3 数据模型
```
product_presets(id, name, brand?, category, form, emoji, color,
                unit, serving_desc, source?, source_date?,
                is_builtin, is_favorite, updated_at)
product_preset_ingredients(id, preset_id, nutrient_code, amount_per_serving)
```
选中模板 = 把 ingredients 拷进现有 `product_ingredients`。

## 4. 通道 B：AI 提示词 + 粘贴解析

### 4.1 用户流程
```
[🤖 AI 解析录入]
 → 步骤1：点「复制提示词」（写入剪贴板）
 → 步骤2：打开豆包/元宝/Kimi/ChatGPT → 发照片 + 粘贴提示词 → 复制它返回的内容
 → 步骤3：回到本 App 点「粘贴 AI 结果」
 → 解析预览：逐项显示 名称→匹配到的成分→数值/单位，可修正/删除/补充
 → [确认填入] → 进入向导（可继续编辑）→ 可「保存为我的模板」
```
> 全程 App **不联网、不上传**；图片与识别都在用户自己的 AI App 里完成。

### 4.2 规范提示词（PROMPT v1，可复制）
```
# 角色
你是「保健品标签成分识别」助手。

# 任务
识别图片中保健品的【营养成分表】与【配料表】，只提取成分与含量；忽略广告语、功效宣传。

# 规则
1. 含量换算为「每 1 个最小服用单位」（每 1 粒/片/袋/勺）；无法确定则保留原值并在 basis 注明。
2. value 用纯数字；unit 只允许：μg、mg、g、IU、亿CFU、mL。
3. 名称用中文常用名；同一成分多次出现请合并求和。
4. 无法定量的（提取物/草本）value 填 null，禁止编造。
5. 维生素A/D/E 若标签用 IU，请原样输出 IU（不要换算）。
6. 只输出 JSON，不要解释、不要 markdown 代码块。

# 输出格式
{"product_name":"","serving":"1粒","ingredients":[{"name":"","value":0,"unit":"mg","basis":"每粒"}]}
```

### 4.3 输出解析器（App 侧，纯 Dart、可单测）
```
1. 提取 JSON：容错 ```json 围栏 / 前后多余文字 → 取首个 { 到末个 } 再 jsonDecode
2. JSON 失败 → 兼容文本格式：Markdown 表格 / "名称 | 数值 | 单位" 行
3. 名称归一化：别名词典 alias → nutrient_code（覆盖 66 个内置 code + 用户自定义）
   - 命中不到 → 模糊包含匹配 → 仍失败则创建「用户自定义成分」（category=other）
4. 单位归一：IU→规范单位（复用 altFactor）；mg↔g；未知单位保留并告警
5. 数据清洗：value 为空/null 记 0 并标记「含量未知」；同名成分合并求和；负值剔除
6. 产出「候选列表」交给用户确认（标注：已匹配 / 需确认 / 未知 / 单位异常）
```
- **别名词典**：`assets/nutrient_aliases.json`（code → [别名…]），可随版本/远端更新
  - 例：`vd: ["维生素D","维D","VD","维生素D3","胆钙化醇","Vitamin D"]`；`dha:["DHA","二十二碳六烯酸"]`
- **自定义成分**：`nutrients` 增加 `is_builtin` 字段；用户新建成分以 `custom_*` code 存入（仅记录，无参考值）

### 4.4 确认界面（必经）
逐行：`☑ 维生素D  25μg   → 匹配:维生素D` / `⚠ 葡萄籽提取物  100mg  → 归为"其他成分"`
支持：改值/改单位/换成其它成分/删除/新增一行 → [确认填入]

---

## 5. 与端侧 OCR 的关系
- 通道 B（AI 解析）**先做**：快、准、零依赖、零体积。
- 端侧 OCR 拍照（PaddleOCR/ML Kit）作为**后续可选**（P2），二者解析层可复用。
- 架构预留 `OcrEngine` 抽象，未来接入不影响业务层。

---

## 6. 隐私与合规
- App 本身不联网、不采集（AI 步骤在用户自己的第三方 App 内完成）。
- 模板/识别结果均标注「仅供参考，以实物标签为准」，不宣称功效。
- 品牌名仅作识别用途。
